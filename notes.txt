The First Normal Form focuses on achieving atomicity by ensuring that every column in a table contains only single, indivisible values and that no cell holds multiple or repeating groups of data. To satisfy 1NF, a relation must have unique column names and distinct rows identified by a primary key, meaning a table cannot use arrays, lists, or multi-valued fields inside a single cell. If a table contains composite or repeating entries, it must be restructured so that each individual value occupies its own dedicated row.
The Second Normal Form builds directly upon 1NF by requiring the table to be in 1NF and completely eliminating partial dependencies. A partial dependency occurs when a non-prime attribute (an attribute not part of any candidate key) depends on only a proper subset of a composite primary key rather than the entire key. To achieve 2NF, any columns that depend on only part of a composite key must be moved into a separate table where that specific sub-key acts as the primary identifier.
The Third Normal Form requires a relation to already satisfy 2NF while eliminating all transitive functional dependencies. A transitive dependency happens when a non-prime attribute depends on another non-prime attribute, which in turn depends on the primary key (such as A → B and B → C, making A → C). To bring a schema into 3NF, these transitively dependent non-key attributes are extracted into their own separate table, ensuring that every non-prime attribute depends directly and solely on the primary key.
The Boyce-Codd Normal Form—often considered a stricter, more refined version of 3NF—demands that for every non-trivial functional dependency X → Y, the determinant X must be a superkey of the table. This means a table can violate BCNF even if it is in 3NF whenever a non-key attribute functionally determines a candidate key or part of one. Achieving BCNF involves decomposing the relation further so that every single left-hand side of a functional dependency strictly functions as a unique identifier or candidate key.
